# 专家库项目建设进展报告

> 整理日期：2026 年 9 月 19 日\
> 整理依据：项目代码、技术文档、Git 提交记录及当前工作区建设内容

## 一、项目总体情况

本项目是在原有工程教育数据库系统基础上进行二次开发建设的专家库系统。专家库与原系统共用技术底座、账号权限体系和运维环境，在此基础上新增专家信息管理、分级审核、智能检索推荐、统计分析和数据治理等业务能力。

目前，专家库主体功能已经基本建设完成，形成了从“数据入库—分级审核—正式发布—检索推荐—统计分析”的完整业务闭环，已经具备内部试运行和用户验收条件。

综合代码完成情况判断：

- 核心业务功能完成度约为 **90%**；
- 已具备内部试运行条件；
- 正式生产就绪程度约为 **80%～85%**；
- 当前主要处于高级检索优化、数据质量治理、安全加固和上线前收尾阶段。

可向领导简要汇报为：

> 专家库已完成主体功能建设，专家数据管理、三级审核、单位权限、批量导入、统计分析及智能检索推荐等核心功能均已打通，目前已具备内部试运行条件，正在围绕约 2.3 万条专家数据开展检索体验、数据质量和安全性能方面的上线前优化。

## 二、技术架构

系统采用前后端分离架构，并延续原工程教育数据库的 Gin-Vue-Admin 技术体系。

| 层次 | 技术与实现 |
|---|---|
| 前端 | Vue 3、Vite、Element Plus、Pinia、Vue Router、ECharts |
| 后端 | Go 1.20、Gin、GORM，按照 Model／Service／API／Router 分层 |
| 数据库 | MySQL，通过 GORM AutoMigrate 维护表结构 |
| 身份认证 | JWT 登录认证及退出黑名单机制 |
| 接口权限 | Casbin RBAC 接口级权限控制 |
| 数据权限 | 基于用户所属单位和专家归属关系进行数据范围隔离 |
| 业务配置 | 菜单、角色、评分权重、审核开关等通过数据库和数据字典配置 |
| 数据处理 | Excel 批量导入、模板下载、批量审核、结果导出、定时重算 |
| 智能检索 | 关键词匹配、语义向量检索、同义词扩展、综合评分排序、匹配原因解释 |
| 部署方式 | 前后端分离，前端和后端均提供 Dockerfile |

### 2.1 后端结构

专家库后端采用清晰的分层结构：

```text
server/
├── model/ExpertDatabase/       数据模型、请求参数和响应结构
├── service/ExpertDatabase/     业务逻辑、审核、评分和检索实现
├── api/v1/ExpertDatabase/      HTTP 接口控制层
├── router/ExpertDatabase/      接口路由注册
├── initialize/                 数据表迁移和路由装配
└── task/                       定时评分重算等后台任务
```

### 2.2 前端结构

```text
web/src/
├── api/                        专家库接口封装
├── view/beijingExpertDatabase/ 专家库业务页面
├── pinia/                      登录态、菜单和数据字典状态管理
├── router/                     静态及动态路由
└── utils/                      请求、格式化和公共工具
```

前端菜单和业务路由由后端根据用户角色动态下发。不同用户登录后，只能看到其角色有权访问的功能菜单。

### 2.3 当前代码规模

根据当前项目代码统计，专家库模块大致包括：

- 68 个后端 Go 文件；
- 25 个专家库前端页面或接口文件；
- 55 个专家库业务接口路由；
- 10 个后端测试文件；
- 约 70 个自动化测试用例。

## 三、已完成的主要建设内容

### 3.1 专家数据体系

已经建立以专家主档为核心的数据模型，主要覆盖：

- 专家基本信息；
- 学科领域；
- 研究方向及研究关键词；
- 研究成果；
- 决策采纳及领导批示记录；
- 学术兼职；
- 专家标签；
- 所属单位及账号归属；
- 审核状态和审核流转日志；
- 成果、决策影响、职称、社会贡献及综合评分缓存；
- 语义检索向量及缓存数据。

系统已经建设专家综合详情页，可在同一页面集中查看专家基本情况、研究成果、决策影响记录和学术兼职，解决了早期数据分散在多个页面的问题。

### 3.2 三级审核业务闭环

已经完成“个人申报—单位审核—市级审核—正式发布”的完整状态流转：

```text
草稿 → 待单位审核 → 待市级审核 → 已发布
          ↓              ↓
        退回修改        退回修改
```

审核流程已支持：

- 申报人提交和撤回；
- 单位审核员审核本单位数据；
- 市级审核员进行最终审核；
- 审核通过和退回修改；
- 审核意见填写；
- 完整审核历史记录；
- 批量审核；
- 审核流程启停开关；
- 绕过审核直接发布的数据追溯标记。

只有处于“已发布”状态的专家，才会进入正式检索和推荐范围。

### 3.3 角色和权限体系

目前已经建立以下主要角色：

- 系统管理员；
- 专家库个人申报人；
- 单位审核员；
- 市级审核员；
- 专家只读用户。

系统权限采用多层控制：

1. JWT 负责用户身份认证；
2. Casbin 负责接口级角色权限校验；
3. Service 层按单位进行数据范围限制；
4. 按创建人和专家归属关系校验数据所有权；
5. 对成果、采纳记录、兼职和标签等子资源进行归属校验。

因此，单位审核员只能处理本单位提交的数据，普通用户也不能通过直接调用接口越权修改其他专家资料。

### 3.4 批量数据导入和治理

系统已经支持：

- Excel 导入模板下载；
- 专家数据批量导入；
- 批量导入结果汇总；
- 错误数据及错误原因反馈；
- 专家重复数据识别；
- 单位自动匹配；
- 未匹配单位提示；
- 大批量导入性能优化；
- 导入数据的审核流程控制。

针对真实数据导入过程中发现的问题，已完成以下优化：

- 专家去重键由“姓名+单位”调整为“姓名+单位+院系”，避免同校同名专家被误判；
- 将研究方向字段扩容至 2000 字符，避免长文本导致整批导入回滚；
- 为姓名、单位、院系和常用筛选字段增加索引；
- 对单位名称进行标准机构匹配；
- 增加导师类别、开设课程和个人详情来源链接等字段；
- 对本地导入备份和含个人信息的核验材料进行 Git 忽略保护。

开发期间代码注释记录的数据库统计口径约为 **23,661 位已发布专家**。该数字来自开发期间的实际数据统计，正式汇报或上线前应再从生产数据库实时核对。

### 3.5 专家检索与推荐

专家检索已经从早期的普通条件查询，逐步升级为综合检索推荐系统。目前已完成：

- 姓名、单位等结构化检索；
- 学科、职称和区域专长筛选；
- 多关键词联合检索；
- 研究方向、研究关键词、关注议题、成果和标签等跨字段检索；
- 语义向量检索；
- 管理员可维护的同义词词典；
- 每条成果、研究方向和标签的分项语义匹配；
- 检索匹配原因解释；
- 无关键词时按综合实力浏览；
- 检索结果导出；
- 语义向量内存缓存；
- 检索语料批量预取；
- 排序平局稳定打散，避免同一批次或同一单位集中排列。

专家综合推荐分主要由以下指标构成：

- 研究成果得分；
- 决策影响得分；
- 专业技术职称得分；
- 社会贡献得分；
- 本次检索主题相关性。

各级别分值和综合排序权重均通过数据字典配置，管理员调整权重时不需要重新修改代码和发版。
